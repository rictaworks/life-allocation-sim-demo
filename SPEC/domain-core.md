# Domain Core の規則

実装どおりの規則を書きます。正はコードです（`src/core/DomainCore/`）。数値はすべて架空のモデル値で、実在の統計・金融商品・個別の投資判断を示すものではありません（設計書 1.2）。

- Domain Core は netstandard2.1 の純粋な C# です。Unity の DLL と、再計算ホスト（`src/core-host/`）が同じものを使います。
- 規則は Domain Core にだけ書きます。Rails・再計算ホスト・Unity には規則を二重に書きません。
- 副作用はありません。乱数は引数で渡すシード付き乱数だけを使います。同じシード・同じ入力からは、同じ結果になります。
- 金額は円の整数、確率とリターンは万分率（10000 で 100%）の整数です。浮動小数点は使いません。

## 評価ランク（`Config/RankTable.cs`）

上から順に判定し、総資産（貯蓄＋投資評価額）と平均満足度の両方が下限を満たした最初のランクにします。

| ランク | 総資産の下限（円） | 平均満足度の下限 |
|---|---|---|
| `S` | 60,000,000 | 60 |
| `A` | 40,000,000 | 40 |
| `B` | 20,000,000 | 0 |
| `C` | 5,000,000 | 0 |
| `D` | 0 | 0 |

- 破綻（`bankrupt`）は、資産額によらず最下位の `D` です。
- 「生活費を削りすぎて満足度が低い高資産」は、満足度の下限のため `S` や `A` にはなりません。

## 1 年の流れ（`YearSettlement.Advance`）

入力は、状態・配分・難易度・乱数です。

1. 配分を検証します（`Simulator.ValidateAllocation`）。不正なら理由を返して終わります。乱数は使わず、状態も変えません。
2. 乱数を 2 回使います。先にイベントの抽選（`EventDrawer.Draw`）、次に市場のリターン（`DrawReturnBp`）です。どちらも、イベントが無くても必ず使います。
3. 精算します（`Settle`。以下の順番は変えません）。

### 精算の順番

1. **配分**：手取り年収 × 生活費% を生活費枠、× 投資% を投資枠、残りを貯蓄枠にします。円未満は切り捨て、端数は貯蓄枠へ入れます。
2. **生活費判定**：必要生活費 = 基準 × 物価係数 ÷ 10000。生活費枠が必要生活費を超えた分を余剰、足りない分を不足とします。満足度は次の式で増減します。
   - 充足の比率 = 生活費枠 × 10000 ÷ 必要生活費。上限は 15000（1.5 倍）。
   - 差 = 上限を当てはめた比率 − 10000。満足度の増減 = 差 × 2 ÷ 1000（0 に近い方へ切り捨て）。
   - 増減が 0 点で、生活費枠と必要生活費が違うときは、符号に合わせて ±1 点にします（不足は下げ、余剰は上げます）。
   - 満足度は 0〜100 に収めます。
3. **積立**：貯蓄 += 貯蓄枠 + 余剰。投資評価額 += 投資枠。
4. **イベント**：
   - 出費：貯蓄から払い、足りない分は「イベントの不足」として取り崩しへ回します。
   - 臨時収入：貯蓄に加えます。
   - 昇給：累計の昇給額に加えます。次の年からの手取り年収に加わります。
   - 市場：この年のリターンを、イベントの値に置き換えます。
   - 一度きりのイベントは、発生済みの一覧に加えます。
5. **運用**：貯蓄に利息（貯蓄 × 10 ÷ 10000）を付けます。投資評価額 = 投資評価額 × (10000 + リターン) ÷ 10000。0 未満にはしません。
   - 市場のリターンは、平均 400 に振れ幅を足し引きした範囲から一様に決めます（`平均 − 振れ幅 + spread`。spread は 0〜2 × 振れ幅）。
6. **取り崩し**：不足額 = 生活費の不足 + イベントの不足。①貯蓄から充てます。残りは②投資を、その年の評価額で売って充てます。どちらでも足りない分が「未充足」です。
7. **物価**：物価係数 = 物価係数 × 10100 ÷ 10000（1% ずつ上げます。整数の割り算）。
8. **状態判定**：年齢を 1 つ進めます。
   - 未充足が残る：`bankrupt`（破綻。その時点で終了）。
   - 次の年齢が 65 以上：`completed`（完走）。
   - 満足度が 20 未満：生活困窮。`status` は `playing` のまま、`struggling` を `true` にします（再計算ホストの出力）。
   - それ以外：`playing`。
9. **結果**：次の状態（次の年齢・次の年の手取り年収 = 次の年齢の手取り年収 + 累計の昇給額・貯蓄・投資・満足度・物価係数・状態・累計の昇給額・発生済みのイベント）と、その年の内訳を返します。

## 配分の検証（`Simulator.ValidateAllocation`）

判定の順番は次のとおりです。最初に当たった理由を返します。

1. いずれかの項目が負なら `allocation_negative`。
2. いずれかの項目が 5 の倍数でなければ `allocation_step_mismatch`。
3. 合計が 100 でなければ `allocation_sum_mismatch`。

負でなく 5 の倍数で合計が 100 なら、各項目は 0〜100 に収まります。

## 乱数（`SeededRandom`）

- 方式は SplitMix64 です（定数はアルゴリズムで決まる値）。状態の初期値は seed を `ulong` に変換した値です。seed 0 も有効です。
- `NextInt(n)` は棄却法です。余りの範囲に当たる値は捨てて引き直すため、偏りはありません。
- 1 つのゲームでは、乱数を 1 つ作り、開始から終わりまで順に使います。

## 再現（`Replayer.Replay`）

入力は、開始状態・seed・配分の履歴（1 年目から順）です。

- 年ごとに `YearSettlement.Advance` を順に適用します。
- 完走または破綻のあとに配分が来たら、`game_finished` で止めます。`turn_no` はその番号です。
- 配分が不正なら、その年の番号と理由（`allocation_*`）で止めます。
- 最後まで進んだ状態が完走または破綻なら、評価（`Evaluator.Evaluate`）を付けます。プレイ中なら評価は `null` です。

## 評価（`Evaluator.Evaluate`）

完走または破綻の状態と、全年の履歴を入力にします。プレイ中や履歴が空の場合は例外になります。

- 総資産 = 貯蓄 + 投資評価額。
- 平均満足度 = 各年の満足度（精算後）の合計 ÷ 年数（0 に近い方へ切り捨て）。
- 破綻：最終状態が `bankrupt` かどうか。
- 困窮年数：精算後の満足度が 20 未満だった年数。
- 投資の売却年数：取り崩しで投資を売った年数（売った額が 0 より大きい年）。
- ランク：上の表。破綻なら `D`。
- 老後資金のコメント：破綻なら専用の文。それ以外は、総資産が 3000 万円以上か未満かで文を選びます。
- 生活の質のコメント：平均満足度で「高い・ふつう・低め」を選び、困窮年数が 1 以上なら困窮の文を足します。総資産が 3000 万円以上で、平均満足度が 40 未満なら、「高資産だが満足度が低い」の文を足します。
- 備えのコメント：投資を売った年数が 0 なら専用の文、1 以上なら年数を入れた文です。

文言は `Config/EvaluationTexts.cs` にあります。

## 新規ゲーム（`NewGame.Start`）

- 難易度のコードを検証します。空・未指定は `Missing`（`difficulty_missing`）、一覧に無いコードは `Unknown`（`difficulty_unknown`）です。
- 初期状態：年齢 22、手取り年収 2,800,000 円、貯蓄 0、投資 0、満足度 60、物価係数 10000、状態 `playing`、累計の昇給 0、発生済みのイベントなし。

## 自動調整（`AllocationAdjuster`）

Unity の配分スライダーで使います。再計算ホストと Rails は使いません。

- 1 本を動かすと、残りの 2 本を比率で自動調整し、合計を 100 に保ちます。
- 残りの 2 本のうち、動かした時期が古い方が端数を吸収します（初めは貯蓄が吸収します）。
- 比率の配分は 5 の倍数に切り捨てます。両方が 0 のときは同じ重みで分けます。
- 動かせるのは 0〜100 の 5 の倍数だけです。それ以外は例外になります。

## 設計書の補完（実装で決めた点）

設計書の文言だけでは決まらなかった点です。実装の判断として書きます。

- 乱数の方式は SplitMix64。設計書は「シード付き乱数」とだけ定めています。
- seed は 0〜2^63−1 の整数です（ホストが検査します）。
- 配分の検証の順番は、負の値、刻み、合計の順です。
- 満足度の増減は、充足の比率を上限 1.5 倍で見て、10% 刻みの点数を切り捨てで求めます。切り捨てで 0 点になるときは、符号に合わせて ±1 点にします。
- 利息と物価係数は、整数の割り算で求めます（貯蓄 × 0.10%、物価 × 1.01）。
- 破綻の判定は、完走の判定より先に行います。65 歳に達しても未充足が残れば破綻です。
- 平均満足度は、年ごとの満足度の合計を年数で割った整数（切り捨て）です。
- 22 歳の初年度は、イベントの抽選の結果を使いません（乱数は消費します）。
- 市場のリターンは、難易度の範囲で一様に決めます。
